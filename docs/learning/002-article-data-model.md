# 002：CMS 里的文章到底是什么

日期：2026-11-01

## 页面和数据的区别

最初的三篇文章直接写在 `app/page.tsx` 中。这样可以快速展示页面，但文章内容和页面结构混在一起：每增加一篇文章，都必须修改首页代码。

CMS 的思路是把文章作为独立数据保存，页面只负责读取并显示数据。当前阶段先使用 `lib/articles.ts` 模拟数据库，后面接入 MySQL 时，页面的职责不会改变。

## 一篇文章包含什么

- `id`：系统内部唯一编号。
- `slug`：用于文章网址的可读标识。
- `title`：文章标题。
- `excerpt`：文章摘要。
- `content`：文章正文。
- `category`：文章分类。
- `status`：`draft` 草稿或 `published` 已发布。
- `publishedAt`：真正对外发布的时间；草稿没有发布时间。
- `createdAt` / `updatedAt`：创建和最后修改时间。

## 为什么要有草稿和发布状态

文章写完之前不能被访客看到。公开主页调用 `getPublishedArticles()`，只返回状态为 `published` 的文章。管理后台以后可以读取全部文章，因此管理员仍能继续编辑草稿。

这条规则可以概括为：数据可以存在，但只有满足发布条件的数据才能公开展示。

## 下一步

为已发布文章建立详情页，让 `slug` 真正成为可访问的网址，然后再把临时数据迁移到数据库。
