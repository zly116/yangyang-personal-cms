# 006：为什么后台能看到草稿，公开网站却不能

日期：2026-11-01

## 同一份数据，不同的访问边界

文章都保存在 MySQL 的 `Article` 表中。公开网站和管理后台没有使用两套文章数据，它们的区别在查询条件和访问权限。

- 公开首页和详情页查询时必须满足 `status = PUBLISHED`。
- 后台文章列表在服务端验证管理员 Session 后，查询所有状态的文章。

草稿不是靠 CSS 隐藏，也不是返回浏览器后再由前端过滤。公开查询从数据库取数时就排除了草稿，因此访客不会收到草稿内容。

## 为什么先实现只读列表

文章列表、新增、编辑和删除涉及不同风险。先实现只读列表，可以独立验证：

1. 管理员身份检查是否有效。
2. 后台能否读取全部文章。
3. 公开页面的发布过滤是否仍然有效。
4. 页面能否正确表示草稿和已发布状态。

如果同时加入修改和删除，出现问题时更难判断是查询、表单、校验还是写入逻辑导致。

## 为什么后台也在服务端查询

后台页面先执行 `requireAdmin()`，验证成功后才查询全部文章。这样完整数据不会先发送到未登录浏览器，再依赖前端隐藏。

## 下一步

增加文章创建和编辑表单，并在服务端校验标题、slug、摘要、正文、分类和发布状态。
