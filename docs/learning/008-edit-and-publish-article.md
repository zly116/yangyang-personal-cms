# 008：编辑、发布与下线文章

日期：2026-11-01

## 编辑页为什么使用文章 id

后台编辑地址使用 `/admin/articles/[id]/edit`。id 是数据库内部稳定主键，即使管理员修改 slug，后台仍能定位同一篇文章。公开详情页继续使用更易阅读的 slug。

## 发布时间规则

- 草稿首次发布：把 `publishedAt` 设置为当前时间。
- 已发布文章修改内容并继续发布：保留原来的 `publishedAt`。
- 已发布文章保存为草稿：视为下线，状态改为 `DRAFT`，清空 `publishedAt`。
- 下线文章再次发布：产生新的 `publishedAt`。

`updatedAt` 由 Prisma 在每次修改时自动更新，因此“首次/本次公开时间”和“最后编辑时间”不会混为一个字段。

## 为什么修改标题不自动修改 slug

标题是展示内容，可以经常优化；slug 是公开网址的一部分。若标题每次变化都自动修改 slug，之前分享的链接会失效。因此编辑页默认保留原 slug，只允许管理员明确修改，并提示修改网址的后果。

正式产品还可以增加旧 slug 重定向表，让旧网址以 301 状态跳转到新网址。第一版尚未实现这一增强功能。

## 为什么更新 Action 重新查询原文章

服务端不能相信浏览器提交的“原状态”或“原发布时间”。Action 使用 id 从数据库重新读取文章，再决定是否保留 `publishedAt`。这可以避免请求伪造旧状态，确保状态转换基于数据库真实值。

## 缓存刷新

文章修改后需要刷新公开首页、旧详情网址、新详情网址、后台概览和文章列表。这样管理员返回列表或访客访问文章时能看到最新结果。

## 当前限制

- 修改 slug 后还没有为旧网址建立重定向。
- 没有版本历史，保存后不能恢复之前的正文。
- 多管理员同时编辑时没有乐观锁或冲突提示。
- 删除文章尚未实现。
