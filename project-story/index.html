01 · SYSTEM

系统如何协作

前台负责展示，后台负责管理，API 负责连接，数据库负责保存。职责分开后，修改文章不再需要改代码。

Next.js 前台

生成公开页面，读取已发布内容，并处理访客评论提交。

NocoBase 后台

让管理员通过表格和表单维护资料、文章与审核状态。

MySQL 数据库

持久保存资料、文章、评论及它们之间的关联关系。

Cloudflare

提供 HTTPS 公网入口，应用和数据库端口不直接暴露。

04 · JOURNEY

从想法到上线

项目经历了调研、手写、迁移和上线。保留第一版不是浪费，它帮助我理解后来交给 NocoBase 的每项能力。

  1. 01

    理解问题

    调研 CMS 与 WordPress

    先明确内容管理系统为什么存在，以及公开网站与管理界面的区别。
  2. 02

    建立基础

    手写第一版 CMS

    使用 Next.js、Prisma 和 MySQL 实现文章、登录、软删除和评论审核。
  3. 03

    调整架构

    迁移到 NocoBase

    建立集合、导入数据、配置最小权限 API Token，并让前台切换数据源。
  4. 04

    形成闭环

    完成评论审核

    访客提交 PENDING 评论，管理员审核后，前台只展示 APPROVED 内容。
  5. 05

    生产交付

    Docker 与 Cloudflare 上线

    双域名 HTTPS、数据库备份、部署手册和验收清单全部完成。

05 · DECISIONS

关键选择与收获

01

先完成闭环，再增加功能

能新增文章不等于 CMS 完成。只有读取、发布、评论和审核都实际走通，才算交付。

02

权限比“接口能用”更重要

公开网站使用独立的最小权限 Token，不能借用管理员权限，也不能直接批准评论。

03

数据卷不等于备份

容器数据持久化只能防止普通重建丢失；生产数据仍需独立导出并异地保存。
